# MyTrade — контекст проекта для Claude

## Комментарии в коде (обязательно)

Пользователь — некодер (системный аналитик), сам код не правит. Код «под ключ» обязан быть
самодокументируемым — комментарии пишутся ДЛЯ СЛЕДУЮЩЕЙ СЕССИИ Claude (контекст между
сессиями теряется, комментарии = опора).

- **Модульный docstring** с разделом «ПРОБЛЕМА/зачем» у нетривиальных модулей
  (пример: `src/mytrade/core/compute.py` — почему BLAS=1 и почему fork ломает env-подход).
- **Inline-комментарии на неочевидных решениях**: ЗАЧЕМ и ПОЧЕМУ ИМЕННО ТАК, а не пересказ
  кода. Пересказ строки — шум, его не писать.
- **Конвенция `AI:`** — новые нетривиальные места (неочевидные инварианты, грабли, боевые
  случаи) помечать комментарием с префиксом `AI:`. Это greppable-тег: один `grep -rn "AI:"`
  показывает все опасные места кодовой базы без всякой инфраструктуры. Старые комментарии
  задним числом НЕ ретрофитим. (Конвенция общая с проектом staffing пользователя.)
- **Помечать связь с задачей** (напр. `# 26.3.3`, `# INFRA-4`) — по метке ищется контекст
  в планах (`docs/`) и истории git.
- Соблюдать плотность и стиль окружающего кода: он комментирован по-русски и по делу.

## Безопасность данных БД (обязательно)

Накопитель на узле (~300М+ баров, месяцы кронов) — НЕВОСПОЛНИМАЯ ценность проекта.

- **`drop_all` (data/schema.py) НЕ вызывать ни из тестов, ни из скриптов, ни «для чистоты».**
  Единственный легитимный вызов — руками, по явной команде юзера, с пониманием «какая БД
  сконфигурирована сейчас». Тесты работают с той БД, что в конфиге: pytest, запущенный на
  узле, с drop_all в тесте = снесённый накопитель (чуть не случилось 14.07, K0).
- В тестах разрушающие операции — только над объектами БЕЗ данных (пример: схема `market`,
  в ней одни вьюхи — восстанавливается из DDL) или над временными таблицами.
- Любой новый деструктив (DROP/DELETE/TRUNCATE) в коде — стоп и вопрос юзеру; в накопителе
  данных `DELETE` нет by design (INFRA-5: даже делистнутые не удаляются).

## Рамки проекта и стек

Рынки: РФ (MOEX) + крипта. **Боевые площадки: РФ — только T-Invest** (адаптер второго
российского брокера лежит в коде как опция), **крипта — Bybit**; архитектура
broker-agnostic. Стек: **Python 3.13 + uv** (src-layout, пакет `mytrade`), TimescaleDB.
Репо: приватный, ветка `main`.

Правила воркфлоу (ветки/мерж/тесты), состояние проекта и точка возобновления — в

и журналы прогонов — в страт-доках `docs/стратегии/*.md`** (у каждой стратегии свой;
статусных сеток вне страт-доков нет). **Операционные грабли расчётного узла —
`deploy/compute-node/README.md`** (читать перед работой на узле). Отвечать пользователю
по-русски.
