# students — правила проекта для архитектора

Рабочее пространство ментора, который готовит фулстек-аналитиков (бизнес-школа, вуз, личное
менторство). Система снимает рутину подготовки и хранения, **но не подменяет суждение**.
Отвечать PO **по-русски**. Дорожная карта — `docs/План и реализация.md`.

> Свод правил для **любого** архитектора (Claude Opus · Kimi K3 · Qwen 3.8Max), не только для
> Claude; имя историческое. Точка входа для не-Claude агентов — `AGENTS.md`.
> Здесь только то, что нужно в КАЖДОЙ сессии. Остальное — по карте, открывать ПО ЗАДАЧЕ.

## ⛔ КРИТИЧНО: персональные данные

В репозитории живые люди: ФИО, контакты, даты рождения, оценки, видеозаписи встреч.

- **⛔ Не в git и не наружу:** `Студенты/`, `Презентации/`, `Вики/`, `.env`, видео и аудио.
  Репозиторий приватный, но это не повод: `git add -f` по этим путям = публикация персональных
  данных.
- **⛔ Кодеры и субагенты данных не видят** — они внешние облачные модели. В наряд не попадают ни
  содержимое этих каталогов, ни ФИО; наряд говорит о **структуре и формате**, фикстуры только
  синтетические. Первый прогон по реальным данным делает архитектор.
  Подробно — `docs/practices/Роли и воркфлоу.md` §7.
- Здесь же в рабочем файле идёт ещё один каталог с закрытыми материалами и правило по нему —
  жёсткое, но светить его в публичном репозитории я не могу.

## Что где лежит

- **`Студенты/`, `Вики/`, `Презентации/` — НЕ в git.** **`data/` — НЕ в git** (`students.db`,
  регенерируется импортом). Код и документы (`mentor/`, `tools/`, `scripts/`, `tests/`, `docs/`)
  — в git.

## Три правила, которые нарушаются чаще всего

1. **⛔ Канон не сочиняется — сверяется.** Устойчивые блоки (например «Дополнительно» в итогах)
   переносятся ДОСЛОВНО; канон = версия, повторяющаяся из раза в раз, **а не последний файл**.
2. **⛔ Источник правды — файл, который PO правил руками**, машинная версия отстаёт. Метрики и
   состав берутся из него; генератор после ручных правок не гоняем.
3. **⛔ Скоуп не расширяется.** «Подготовь итоги» = файл итогов, и только он. Смежные документы
   не правим без явной команды PO. Обоснования — `docs/practices/уроки-агента.md`.

## Роли и кодер — коротко

- **PO — Владимир** (методика, продукт, приёмка). **Архитекторы** — Claude Opus, Kimi K3,
  Qwen 3.8Max: равны, взаимозаменяемы, запретных зон между ними нет. **Кодер — DeepSeek**
  через **Kilo CLI** в автономном цикле, изолированный worktree, в `main` не мержит.
- **PO приходит с задачей на уровне ценности** — архитектор сам её изучает, решает «разовая
  работа / методика / эпик» и **сам делит на наряд и распределяет исполнителей**. PO задаёт
  только режим запуска цикла и принимает результат.
- **⛔ «Функционал» ≠ «код».** Смысловые артефакты пишет архитектор, читая исходники; код даёт
  конвейер, хранилище и проверки. Задач «сгенерируй итоги автоматически» не бывает.
- **⛔ Граница документов:** `docs/План и реализация.md` = ЭПИКИ, `docs/наряды/` = ЗАДАЧИ. Новую задачу
  в план не заводим. Задача = своя ветка, мерж в `main` сразу после приёмки.
- **Кодерам — только механичное, изолированное от данных, с машинной проверкой ≥⅔ задач батча.**
  Сдача — зелёный гейт; красный гейт = возврат без разбора; два прохода архитектора максимум.
- **⛔ ЕДИНИЦА ИЗМЕРЕНИЯ — НЕДЕЛЬНЫЙ ЛИМИТ АРХИТЕКТОРА, НЕ ДЕНЬГИ** (решение PO 11.08): у PO
  подписки, дефицитен недельный/месячный лимит — свой у Claude, Kimi, Qwen. **Кодер бесплатен по
  всем фронтам**, круги стоят ноль, и разделение работы с ним нужно ровно для сбережения лимита.
  Порог «по объёму задачи» снят: ограничитель — стоимость моей оснастки (наряд + планка + приёмка).
- **⭐ Расход ≈ длина контекста × число запросов**, вывод — доли процента. Отсюда **«фаза =
  сессия»**: наряд и планка — одна сессия, прогон и приёмка — другая. Читать точечно, тяжёлый
  вывод — в файл, в контекст только хвост. Приёмы — `docs/наряды/README.md` §11.
- **⛔ После каждого наряда — строка ⏱ «мой расход + вердикт»** (`docs/наряды/README.md` §11).
  Пишется всегда и сама; отрицательный итог не сглаживается. Расход кодера не считаем.
- **⛔ Максимум ОДИН субагент на задачу, и только по прямой просьбе PO.**
- **Качество выше лимита и времени.** ⛔ Не сокращаем ответы и не срезаем проверки — экономим
  структурой сессии, а не глубиной работы.

## Окружение и код — коротко

Python — **uv**, венв `.venv` на 3.13, запуск через `.venv/bin/python …`, НЕ системным python.
Правку кода без зелёного `.venv/bin/python -m pytest -q` не сдаём; тесты в сеть не ходят и
реальных данных не касаются. Код самодокументируемый: docstring «зачем», inline на неочевидном,
`AI:`-тег на новых граблях, метка задачи наряда, по-русски. Docker не вводим — пишем
**Docker-ready**. Стек и грабли предметной области — `docs/practices/код-и-тесты.md`.

## Память архитектора

**В памяти — ТОЛЬКО состояние и правила поведения.** Фактура вся в git и в локальных доках.
Нашёл в памяти деталь, которой место в доке, — перенеси, а не дублируй. Про студентов (этапы,
оценки, оговорки) в памяти не пишем вообще: для этого есть
`Студенты/_Реестр студентов.md`, планы xlsx и `python -m mentor info`.
