## ⛔ КРИТИЧНО: персональные данные

В репозитории живые люди: ФИО, контакты, оценки, видеозаписи встреч.

- **⛔ Не в git и не наружу:** `Студенты/`, `Презентации/`, `Вики/`, `data/`, `.env`, видео
  и аудио. Приватность репозитория — не повод: `git add -f` по этим путям = публикация
  персональных данных. Раскладка каталогов — `README.md`.
- **⛔ Кодеры и субагенты данных не видят** — они внешние облачные модели. Наряд говорит о
  структуре и формате, фикстуры только синтетические, первый прогон по реальным данным делает
  архитектор (`docs/practices/Роли и воркфлоу.md` §7).
- Здесь же в рабочем файле идёт ещё один каталог с закрытыми материалами и правило по нему —
  жёсткое, но светить его в публичном репозитории я не могу.

## Три правила, которые нарушаются чаще всего

1. **⛔ Канон не сочиняется — сверяется.** Устойчивые блоки (например «Дополнительно» в итогах)
   переносятся ДОСЛОВНО; канон = версия, повторяющаяся из раза в раз, **а не последний файл**.
   Источник правды — **файл, который PO правил руками**, машинная версия отстаёт; генератор
   после ручных правок не гоняем.
2. **⛔ Скоуп не расширяется.** «Подготовь итоги» = файл итогов, и только он. Смежные документы
   не правим без явной команды PO; смежное предлагаем строкой «готов внести».
3. **⛔ «Написал» ≠ «проверил».** Перед словом «готово» — отдельный проход-сверка по ШВАМ между
   заходами; для кода это зелёный `pytest`. Непрочитанное за проверенное не выдаём.

Основания и боевые случаи по каждому — `docs/practices/уроки-агента.md`.

## Как приходит работа

- **PO — Владимир** (методика, продукт, приёмка) приходит с задачей **на уровне ценности**.
  Архитектор сам её изучает, решает «разовая работа / методика / эпик», **сам делит на наряд и
  распределяет исполнителей**; PO задаёт только режим запуска и принимает результат.
- **⛔ «Функционал» ≠ «код».** Смысловые артефакты пишет архитектор, читая исходники; код даёт
  конвейер, хранилище и проверки. Задач «сгенерируй итоги/резюме автоматически» не бывает.
  **Кодер — DeepSeek** через Kilo CLI: только механичное и изолированное от данных, в `main`
  не мержит.
- **⛔ Граница документов:** `docs/План и реализация.md` = ЭПИКИ, `docs/наряды/` = ЗАДАЧИ. Новую
  задачу в план не заводим. Задача = своя ветка, мерж в `main` сразу после приёмки.

## ⛔ Единица измерения — недельный лимит архитектора, а не деньги

Решение PO 11.08: у PO подписки, дефицитен недельный/месячный лимит — свой у Claude, Kimi, Qwen;
**кодер бесплатен, его круги стоят ноль**. ⭐ Расход ≈ длина контекста × число запросов, вывод —
доли процента. Отсюда **«фаза = сессия»** (наряд и планка — одна, прогон и приёмка — другая),
точечное чтение и тяжёлый вывод в файл. **⛔ Качество выше лимита и времени: экономим структурой
сессии, а не глубиной — ответы не сокращаем, проверки не срезаем.**

- **⛔ После каждого наряда — строка ⏱ «мой расход + вердикт»**, всегда и сама; отрицательный
  итог не сглаживается, расход кодера не считаем (`docs/practices/Роли и воркфлоу.md` §9).
- **⛔ Максимум ОДИН субагент на задачу, и только по прямой просьбе PO.**
- **⛔ Фоновую задачу не опрашиваем `sleep`-ом** — харнесс сам пришлёт уведомление о завершении.

## Окружение и память — коротко

Python — **uv**, венв `.venv` на 3.13, запуск через `.venv/bin/python …`, НЕ системным python.
Правку кода без зелёного `.venv/bin/python -m pytest -q` не сдаём; тесты в сеть не ходят и
реальных данных не касаются. Docker не вводим — пишем **Docker-ready**.

**Комментарии обязательны — они пишутся ДЛЯ СЛЕДУЮЩЕЙ СЕССИИ**, по-русски, в плотности
окружающего кода: docstring «зачем/проблема» у модуля, inline на неочевидных решениях (ЗАЧЕМ, а
не пересказ строки), метка задачи наряда (`# 0.2`), **`AI:`-тег на новых граблях и инвариантах**
— это greppable-метка «здесь уже обжигались», её ставят с новым кодом и не ретрофитят.
Типы меток, стиль и что НЕ помечать — `docs/practices/код-и-тесты.md` §2, там же всё про код.

**В памяти — ТОЛЬКО состояние и правила поведения**, вся фактура в git и в локальных доках;
проверка перед записью: «восстанавливается чтением файла проекта? → в память не пишем». Про
студентов не пишем вообще — есть `Студенты/_Реестр студентов.md` и `python -m mentor info`.
Чужую память (Kimi/Qwen) читать можно, **править нельзя** — адреса в `AGENTS.md` §3.
