# Код, комментарии, тесты, окружение

> **Когда открывать:** когда пишешь или правишь код (`scripts/`, `api/`, `frontend/`, `tests/`).
> Для аналитических сессий (разбор отчётности, новостей, решения по капиталу) этот док не нужен.
> Вынесено из `CLAUDE.md`, чтобы не грузить правила кода в каждую сессию.

---

## 1. Окружение

**Python на маке — через `uv`, НЕ через brew.** Интерпретаторы в `~/.local/share/uv/python/`,
венв проекта — `reports/`. `brew install python@3.13` PO останавливает.
**Почему:** венв не переносится между машинами (при переезде скопированный `reports/` битый),
а Python PO держит в uv.

```bash
rm -rf reports && uv venv reports --python 3.13
source reports/bin/activate
uv pip install -r requirements.txt --extra-index-url \
  https://opensource.tbank.ru/api/v4/projects/238/packages/pypi/simple
```

- Системные бинарники (tesseract, ffmpeg) — через brew, но **спрашивать перед установкой**.
- Видео-зависимости — отдельный `requirements-video.txt` (mlx = Apple-only, сломал бы Docker/Linux-сервер).
- Секреты — `.env` (gitignored); доступ к серверу новостей — `deploy/.deploy.env` (`NEWS_*`).

## 2. Комментарии (обязательно)

PO — «вайбкодер»: просит сначала план/архитектуру, код правит сам вместе с агентом. Код обязан
быть самодокументируемым — **комментарии пишутся ДЛЯ СЛЕДУЮЩЕЙ СЕССИИ** (контекст между
сессиями теряется, комментарии = опора).

- **Модульный docstring** с разделом «зачем/проблема» у каждого нетривиального модуля: что
  делает, откуда данные, куда пишет, как запускать (образец — шапки в `scripts/`).
- **Inline-комментарии на неочевидных решениях:** ЗАЧЕМ и ПОЧЕМУ ИМЕННО ТАК, а не пересказ кода.
  Пересказ строки — шум, его не писать. (Пример: почему `value_mln` масштабируем только для
  currency-концептов в `scripts/ingest.py`.)
- **Конвенция `AI:`** — новые нетривиальные места (неочевидные инварианты, грабли, боевые случаи)
  помечать комментарием с префиксом `AI:`. Greppable-тег: один `grep -rn "AI:" scripts/` показывает
  все опасные места без всякой инфраструктуры. Старые комментарии задним числом НЕ ретрофитим.
- **Помечать связь с задачей** плана (`# A1`, `# B6`) — по метке ищется контекст в
  `docs/План и реализация.md` и в истории git.
- Соблюдать плотность и стиль окружающего кода: он комментирован по-русски и по делу.

## 3. Тесты (обязательно после КАЖДОЙ правки)

**Правку без прогона не сдаём.** Изменилось или добавилось поведение — написать/обновить тест,
затем прогнать весь набор и убедиться, что зелено, прежде чем считать задачу сделанной.

- Тесты — в `tests/`, pytest ставится **в венв `reports/`** (`uv pip install pytest`), НЕ через brew.
- Запуск: `source reports/bin/activate && pytest -q`. Конфиг — `pytest.ini` (`testpaths=tests`);
  `tests/conftest.py` кладёт `scripts/` в `sys.path` (скрипты — не пакет).
- ⚠️ **Канон — именно `pytest -q`.** Если набор зелёный только под другой командой (напр.
  `python -b -m pytest`, где CWD попадает в `sys.path`) — это дефект, а не «зелено».

### Что покрываем в первую очередь

Чистая логика (тождества валидатора, масштаб `value_mln`, формулы `compute`/`sync_portfolio`)
и **инварианты схемы** (персистентные таблицы переживают пересборку `ingest`, дедупы-индексы
срабатывают).

### ⛔ Тесты НИКОГДА не ходят в сеть и в боевые API

T-Invest, MOEX, ЦБ, сервер новостей, узел данных, PDF — либо мокать, либо тестировать чистую функцию отдельно
от ввода-вывода. Паттерн для скриптов с DB-константой: `monkeypatch.setattr(mod, "DB", tmp_path/...)`.

### ⚠️ Фикстуры повторяют БОЕВУЮ схему, а не удобную выдуманную

Фикстура, написанная под свою же реализацию, даёт зелёный тест и тихий дефект. Обожглись дважды. Правила:

1. **Схема тест-БД — из `ingest.SCHEMA_SQL`**, а не свои `CREATE TABLE`
  (`conn.executescript(ingest.SCHEMA_SQL)` + INSERT нужных строк; образцы: `tests/test_evening.py`,
  `tests/test_push_restrictions.py`, `tests/test_ingest_schema.py`). Новостные таблицы — из
  `scripts/news_schema.sql` (у `news_link` PK составной `(news_id, url)`, **колонки `id` НЕТ**).
2. **Словарные значения — реальные, из БД.** Строки, по которым код фильтрует (`metric.name`,
  `holding.type`, `portfolios.strategy`, `company.category`/`sector`), проверять `SELECT DISTINCT`
  по боевой БД. Выдуманное значение = тест зелёный, боевой ответ пустой.
3. **Фейки — экземпляры настоящих классов.** Подменяешь `portfolios.load_portfolios` — собирай
  объекты того же класса, что в бою. Самописный dataclass с удобными полями маскирует ровно то,
  что сломается.
4. **Данные в фикстуре повторяют боевую ФОРМУ, а не идеальную.** В бою бумага лежит в нескольких
  портфелях (зеркальные Свой+ИИС), часть колонок NULL, ряды начинаются в разные даты — так и в
  фикстуре.
5. **Перед сдачей — прогон на БОЕВОЙ БД (read-only).** Пустой список, нули или `null` там, где в
  БД данные есть, — провал сдачи, а не «зелено». Тест на фикстуре и прогон на реальных данных —
  РАЗНЫЕ проверки, нужны обе.
6. ⛔ **Но в `assert` идёт ИНВАРИАНТ, а не снимок живых данных.** Тест, гоняемый на боевых RAW/БД,
  проверяет то, что верно ВСЕГДА (счёт сходится, код возврата соответствует состоянию, сумма
  частей равна итогу), — и никогда конкретное «N из M» живого тикера: оно меняется от нашей же
  работы, и тест начинает краснеть за ПРОГРЕСС, а не за дефект. Поймано 17.08.2026:
  `test_cli_real_raw_measure` вбивал «<ЭМИТЕНТ>/РСБУ закрыто 4 из 10» как эталон, разбор
  B1-<ЭМИТЕНТ>-COV закрыл строку до 10 из 10 — и гейт упал на здоровом изменении. Чинится не
  подкруткой числа (протухнет снова у следующего эмитента), а переходом на инвариант:
  `closed + empty == window_size` и `rc == (1 if empty else 0)`. **Признак болезни: чтобы
  тест позеленел, надо править ожидание после каждой законной правки данных.**
6. **⚠️ Добавляешь колонку в персистентную таблицу — сначала посчитай, что сломается в тестах.**
  Правило 1 соблюдено не везде: часть фикстур всё ещё пишет свой `CREATE TABLE`, а вставляет
  ПОЗИЦИОННО (`INSERT INTO t VALUES (...)`). Такая вставка ломается от любой новой колонки, даже
  nullable и добавленной в конец. 08.08.2026 добавление `price_weekly.as_of` уронило **29 тестов**
  в пяти файлах — не из-за логики, а из-за формы фикстур. Порядок правки: (1) колонка в
  `SCHEMA_SQL`, (2) идемпотентная `migrate_*` (persist-таблицы `CREATE IF NOT EXISTS` не
  расширяет — образцы `migrate_fx_daily`, `migrate_price_weekly`), (3) фикстуры к боевой схеме,
  (4) позиционные вставки → именованные. **Именованная вставка в фикстуре — не педантизм, а
  единственное, что переживает расширение схемы.**

7. **⛔ Ни один тест не знает БОЕВОГО пути к БД — даже тот, что «про другое».** Подменять
  константу пути (`monkeypatch.setattr(PW, "DB", tmp_path / "db.sqlite")`) нужно и там, где
  проверяется поведение при недоступном хабе: `sqlite3.connect` несуществующий файл **создаёт**.
  На машине с боевой БД дефект невидим — тест молча читает боевые данные; в чистой рабочей копии
  кодера он создаёт пустой `db/reports.sqlite` и **обрывает автономный цикл** как порчу БД
  (поймано на канарейке PER-1, 11.08.2026). Мокать хаб, но не путь — половина изоляции.

8. **⛔ Зашитая дата в фикстуре — мина замедленного действия.** Всё, что код фильтрует по
  «сегодня» (вахты `date >= today`, окна цен, дедлайны, TTL), в фикстуре задаётся ТОЛЬКО
  относительно `date.today()` — хелпер вида `_day(+7)` / `_day(-14)` (образец —
  `tests/test_api_p2.py`). Дата-литерал делает тест зелёным ровно до своего наступления, а потом
  роняет его **сам по себе, без единой правки кода** — и краснота выглядит как регресс, которого
  не было. 16.08.2026 так покраснели `test_watches_endpoint` и `test_watches_endpoint_hides_closed`:
  вахты сидели на `2026-08-15`, `/watches` отдавал корректный пустой список. Проверка на весь
  репозиторий — прогон со сдвинутыми часами (плагин подменяет `date.today()` в уже
  импортированных модулях: они делают `from datetime import date`), горизонты +30/+120/+400 дней.

> **Боевой пример.** 63 своих теста зелёные, а на боевой БД: `/emitters`
> всегда пуст (искали `name='P/E'`, `'ROE'` — в БД `P/E (тек. цена)`, `ROE (годовая)`);
> `portfolio_id=0` у всех (у настоящего `Portfolio` нет поля `id`, а фейк в тесте его имел);
> бумаги задвоены (в фикстуре не было зеркал Свой+ИИС); сектор пуст у трёх бумаг (брали из
> `company` в БД — 28/52, вместо `companies.yaml` — 52/52). Ни один из четырёх дефектов не мог
> быть пойман фикстурой, написанной под свою же реализацию.

## 4. Архитектурные принципы для нового кода

- **Всё в Docker** (даже если сейчас гоняется локально — готовим к переезду на сервер).
  **«Всё в докере» = всё, кроме физически привязанного к маку/десктопу** — осознанные
  host-исключения: **сервер новостей** (systemd, эпик U), **Anytype-desktop** (витрина, localhost-API),
  **mlx-видео** (Apple-only, эпик I), **launchd-кроны** (маковые снапшоты).
- **Тесты — бэк + фронт + e2e**, внешние сети ВСЕГДА мокаются.
- **Стек (зафиксирован по образцу `staffing` — зрелый — и `paperbirds`):**
  - *API-бэк:* FastAPI + uvicorn + pydantic; чтение `reports.sqlite` голым `sqlite3` (read-only;
  БЕЗ alembic/celery/SQLAlchemy — reports регенерит БД из RAW, не мигрирует).
  - *Фронт:* React + Vite + TypeScript + Ant Design + axios + react-router; общие компоненты — `ui-kit/`.
  - *Тесты:* pytest + respx (бэк), Vitest + Testing Library + MSW (фронт), Playwright e2e (браузер
  ВНУТРИ проекта `PLAYWRIGHT_BROWSERS_PATH=0`, изолированный `docker-compose.e2e.yml`).
  - *Контракт:* OpenAPI-генерация (`docs/openapi.yaml`) — договор фронта и бэка.
